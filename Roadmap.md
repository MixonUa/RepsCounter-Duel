# Roadmap — план разработки Reps Counter

> Поэтапный план. Требования — в `CLAUDE.md`, текущее состояние кода — в `ProjectTree.md`.
> Экраны взяты из описания макета Figma (2026-11-19); доступ Figma MCP к файлу пока не получен, точные размеры и цвета будут сверены позже.
> Статусы: ✅ готово · 🚧 в работе · 📋 запланировано

**Последнее обновление:** 2026-11-20 — рабочая версия: все экраны, сервер (регистрация, друзья, дуэли, рейтинг) и подсчёт повторов на фронтальной камере; первая проверка на iPhone пройдена. Остались доработки и подготовка к релизу (внизу).

## Принятые решения по макету (2026-11-19)
- Везде одна сумма повторений из дуэлей (приседания + отжимания), без разделения по упражнениям; тренировки не учитываются.
- Без разрешения камеры в приложение не пускаем (экран «подсказки по камере» + «Open Settings»). Риск App Review 5.1.1 — перепроверить перед релизом.
- В карточке найденного игрока виден список его друзей.
- Выбор мотивации в онбординге — только для вовлечения, на сервер не сохраняется.
- Входящая заявка в друзья: всплывающий экран (Accept / Decline / ✕); после ✕ — плашка сверху на всех табах до ответа.
- Рекорды тренировок храним по упражнению; где нужно — показываем сумму.
- В онбординге есть пейвол (3 дня бесплатно, затем $6.99/неделю); пока только UI с тестовыми покупками. Что даёт подписка, цены и StoreKit — открытые вопросы (см. `CLAUDE.md` §11).

## Этапы

### Этап 0. Фундамент ✅
- Локальный Swift-пакет: `DesignSystem`, `ExerciseAnalyzer`, `Backend`.
- Каркас приложения: свой таббар Home / Rating / Profile + отдельная кнопка Duel, навигация, mock-данные.
- Liquid Glass на iOS 26+ и фолбэк для iOS 18–25.
- `supabase-swift` (закреплённая версия), dev-проект Supabase — только по команде.
- Токены дизайна пока системные; уточняются в «Этапе UI» по скриншотам и при доступе к Figma MCP.

### Этап UI. Вёрстка всех экранов на тестовых данных ✅
Цель: всё приложение можно пройти в симуляторе — все экраны, переходы и состояния (пустые, ошибки, загрузка) — до подключения сервера и камеры. Источник: скриншоты фреймов Figma (Export → PNG) или описание экрана; точные токены — при доступе к Figma MCP.
Порядок:
1. ✅ Онбординг: ✅ вводные слайды 1–2 → ✅ ник (+ ошибка «занят») → ✅ аватар-эмодзи → ✅ «Profile Is Ready» (+ регистрация на тестовом сервисе) → ✅ цель / мотивация (68%) → ✅ слайды-объяснения 1 (77%) и 2 (87%, анимация списка) → ✅ пейвол (общий макет, тестовые покупки) → ✅ запрос камеры + «доступ запрещён» / Open Settings → разрешение камеры / подсказки по камере (весь поток уже проходится, шаги без макета — заглушки).
2. ✅ Home: пустое и заполненное состояния, недельный график, таббар с кнопкой VS (данные тестовые).
3. ✅ Profile: ✅ профиль, список Friends (see all), Settings, Edit Profile (свой дизайн), Add a Friend, карточка игрока, входящая заявка (лист + плашка на всех табах).
4. ✅ Rating: пустое и заполненное состояния, Global / Friends, подиум, закреплённая своя строка.
5. ✅ Тренировка: ✅ Choose Activity (кнопка VS) и Choose Exercise (общий для тренировки и дуэли, режим передаётся дальше) → ✅ тренировка на фронтальной камере (Start → 3·2·1 → REPS / Finish, без таймера) → ✅ результат (Great Job! / Don't Give Up !, Total Reps и рекорды хранятся на телефоне).
6. ✅ Дуэль: ✅ Choose a Friend (пусто / только заявки / список) → ✅ Set a duel time → ✅ ожидание ответа (Waiting...) → ✅ входящий вызов у соперника (модальный экран + плашка) → ✅ лобби «Ready to duel?» → ✅ отсчёт и дуэль поверх фронтальной камеры → ✅ результат (победа / поражение / ничья).
Правила: экраны берут данные через протоколы/модели из `Backend` и `MockData`, чтобы на этапах 1–5 менялся только источник данных, а не вёрстка. Экраны без дизайна помечаются `PROVISIONAL`.

### Этап 0.5. Прототип распознавания позы 🚧
- ✅ Vision → точки тела → скелет поверх камеры → подсчёт приседаний и отжиманий спереди (машины состояний, тесты на синтетике), подключено к тренировке и дуэли.
- ✅ Первая проверка на реальном iPhone (2026-11-20, один тестер): тренировка приседаний и отжиманий и дуэль работают.
- 📋 Подбор порогов на разных людях, телефонах, освещении и расстояниях.

### Этап 1. Онбординг и регистрация ✅
- ✅ Dev-проект Supabase, миграции в `supabase/migrations/`.
- ✅ Сервер: анонимная сессия, `profiles`, уникальный ник без учёта регистра (3–20: буквы, цифры, `_`, `.`), RLS, RPC проверки ника; SQL-тест прав в откатываемой транзакции.
- ✅ Онбординг и Edit Profile ходят на сервер; определение новой установки и очистка старой сессии в Keychain.
- ✅ Анонимные входы включены, регистрация проверена на устройствах.
- 📋 Перед публичным запуском: CAPTCHA на анонимный вход; сверка профиля с сервером при запуске (сейчас вход по локальному флагу).

### Этап 2. Профиль и друзья ✅
- ✅ Сервер: `friend_requests`, `friendships`, RPC без ID аккаунтов, лимит заявок; SQL-тест чужого доступа, дублей и встречных заявок.
- ✅ Profile, See all, Add friend, карточка игрока, входящая заявка (опрос раз в 20 с) и Choose a Friend работают с сервером.
- ✅ Статистика и место недели в карточке игрока и в списках друзей.
- ✅ Удаление из друзей и отмена заявки: кнопка в карточке игрока (с подтверждением) и долгое нажатие в списке Friends (временный дизайн).
- 📋 Блокировка (нужен дизайн); realtime вместо опроса.

### Этап 3. Тренировка ✅ (кроме калибровки)
- ✅ CameraService (фронтальная камера), PoseDetection, `ExerciseAnalyzer` (машины состояний + юнит-тесты на синтетике), экраны подключены к камере и анализатору.
- ✅ Рекорды тренировок синхронизируются с сервером (PR в лобби).
- 📋 Калибровка порогов на разных людях и устройствах; SwiftData вместо UserDefaults (по желанию).

### Этап 4. Дуэль ✅
- ✅ Сервер: таблица `duels` (одна вместо четырёх: приглашение, лобби, старт, счёт), RPC жизненного цикла, повторы по порядку в окне времени, идемпотентная финализация; SQL-тест (24 случая).
- ✅ HEAD TO HEAD и результат — настоящая статистика с сервера; рекорды тренировок синхронизируются.
- ✅ Экраны дуэли работают с сервером: вызов, ожидание, входящий вызов, лобби, синхронный старт по серверному времени, отправка повторов, счёт соперника, итог, выход = поражение, Play Again = новый вызов.
- ✅ Обрыв связи: пульс раз в секунду, «Reconnecting…» на экране, после 10 с тишины дуэль «прервана» — без победителя и без рейтинга.
- ✅ Незавершённая дуэль после перезапуска: при открытии приложения окно Resume / Leave, зависшая дуэль больше не блокирует новые вызовы.
- 📋 Realtime / push вместо опроса; спорные результаты.

### Этап 5. Статистика и рейтинг ✅
- ✅ Сервер: недельный рейтинг Global / Friends (с понедельника 00:00 UTC, только завершённые дуэли, равные суммы — одно место), история дуэлей, моя статистика, Top Friends недели — всё считается из таблицы `duels` (без отдельных итоговых таблиц, двойное начисление невозможно); SQL-тест.
- ✅ Home (график недели по локальным дням, последняя дуэль, место и «N reps to top M»), Profile (Duels Won, Win Rate, Total Reps, место, Top Friends) и Rating показывают серверные данные.
- ✅ Экран Duels History по макету (Home → See all): All / Wins / Losses, группировка по дням.
- ✅ «+N this week» у рекордов на Home (рост рекорда с начала недели графика; история рекордов хранится на телефоне).
- 📋 Пагинация рейтинга дальше топ-100, прошлые недели / за всё время (открытый вопрос).

## Что осталось
**Для хорошей рабочей версии**
- Сверка профиля с сервером при запуске (вход сейчас по локальному флагу).
- Перепроверка доступа к камере, если его выключили после онбординга (сейчас экран камеры просто пишет «Camera access is off»).
- SQL-тесты сервера файлами в `supabase/tests` (сейчас гоняются вручную).
- Чистка устаревших комментариев в коде.

**Отложено / открытые вопросы**

- Рекорд тренировки: зависит ли от длительности (решено: по упражнению).
- Прошлые недели / рейтинг за всё время, пагинация дальше топ-100.
- Удаление аккаунта и очистка брошенных профилей; монетизация (StoreKit); Contact us / Privacy / Terms.
